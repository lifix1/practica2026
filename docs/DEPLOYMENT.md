# Руководство по развёртыванию и эксплуатации (Production)

Документ описывает настройку окружения, подключение внешней базы данных PostgreSQL, сборку, деплой на платформу Render.com (в связке с Neon.tech) и регламент передачи системы в эксплуатацию.

---

## 1. Переменные окружения

Шаблон переменных находится в `.env.example`.

| Переменная | Обязательна в Prod | Описание |
| --- | --- | --- |
| `DATABASE_URL` | Да | Строка подключения PostgreSQL (например, Neon.tech: `postgresql://user:pass@host/db?sslmode=require`). Альтернативно поддерживается `POSTGRES_URL` или набор `SQL_HOST`, `SQL_PORT`, `SQL_USER`, `SQL_PASSWORD`, `SQL_DB_NAME`, `SQL_SSL`. |
| `JWT_SECRET` | Да | Секретный ключ для подписи access/refresh JWT (`HS256`). Рекомендуемая длина — **от 32 символов**. Если ключ отсутствует или короче 16 символов, используется эфемерный случайный ключ (сессии будут сбрасываться при каждом рестарте сервера). |
| `APP_URL` | Рекомендуется | Внешний HTTPS-URL приложения (например, `https://university-inventory.onrender.com`). Используется для формирования ссылок внутри QR-кодов при отсутствии заголовка `Host` и при проверке `Origin` для защиты от CSRF. |
| `NODE_ENV` | Да | Установите `production` для отдачи собранной статики из `dist/`, включения production-поведения cookies и генерации стойкого bootstrap-пароля. |
| `SEED_ADMIN_PASSWORD` | Опционально | Начальный пароль для учётной записи `admin`, если база данных пуста. Если не задан в `production`, сервер сгенерирует случайный пароль при первом запуске и выведет его в stdout/логи. |
| `PORT` | Опционально | Порт HTTP-сервера (по умолчанию `3000`). Платформа Render задаёт переменную автоматически. |

### Замечание о SSL к PostgreSQL
В `src/db/index.ts` SSL-соединение включается автоматически для любых не-локальных хостов (`rejectUnauthorized: false`), что совместимо с Neon.tech и Render PostgreSQL. Для принудительного управления можно задать `SQL_SSL=true` или `SQL_SSL=false`.

## 2. Инициализация базы данных

Система использует два дополняющих механизма управления схемой PostgreSQL:

1. **Автоматический bootstrap при старте сервера (`ensureTablesExist` + `seedDatabaseIfEmpty` в `src/db/seed.ts`)**:
   - Выполняется синхронно в `startServer()` до начала приёма HTTP-запросов (критично для «холодного старта» и пустых БД).
   - Создаёт все перечисления (`role_enum`, `data_type_enum`, `writeoff_state_enum`, `issue_state_enum`), все 15 таблиц и индексы журнала аудита, если они ещё не созданы.
   - Проверяет наличие записей в таблице `"user"`. Если таблица пуста, создаёт **единственную** учётную запись `admin` с ролью `ADMIN`. Никакие тестовые пользователи, кабинеты, типы или оборудование не создаются.
2. **Миграция через Drizzle Kit (при необходимости явного обновления схемы)**:
   ```bash
   npm run db:push
   ```
   Использует конфигурацию `src/db/drizzle.config.ts` и файл схемы `src/db/schema.ts`.

## 3. Сборка и запуск на собственном сервере (VPS / Docker / PM2)

1. Клонируйте/перенесите файлы проекта и установите зависимости (требуется Node.js `>= 20`):
   ```bash
   npm ci
   ```
   *(или `npm install`)*
2. Создайте `.env` с рабочими значениями `DATABASE_URL`, `JWT_SECRET`, `APP_URL`, `NODE_ENV=production`.
3. Выполните сборку:
   ```bash
   npm run build
   ```
   В результате:
   - `vite build` собирает клиентскую часть в `dist/`;
   - `esbuild` собирает серверный вход `server.ts` в `dist/server.js`.
4. Запустите приложение:
   ```bash
   npm run start
   ```
5. Настройте reverse proxy (Nginx / Caddy / балансировщик) на перенаправление HTTPS-трафика к порту приложения с передачей заголовков:
   - `Host` / `X-Forwarded-Host`
   - `X-Forwarded-Proto: https`
   - `X-Forwarded-For`

   > На сервере включено `app.set('trust proxy', 1)`. Корректная передача `X-Forwarded-Proto: https` необходима для установки флага `Secure` у auth-cookies и заголовка `Strict-Transport-Security`.

## 4. Деплой на Render.com + Neon.tech

В корне проекта присутствует готовый манифест `render.yaml`:

- **Build Command**: `npm install && npm run build`
- **Start Command**: `node dist/server.js`
- **Health Check Path**: `/api/health`
- **Node Version**: `22`

### Пошаговая настройка
1. Создайте базу данных PostgreSQL в [Neon.tech](https://neon.tech) и скопируйте строку подключения (`DATABASE_URL`).
2. Создайте Web Service на Render.com (вручную или через Blueprint `render.yaml`).
3. Заполните переменные окружения в панели Render:
   - `NODE_ENV` = `production`
   - `DATABASE_URL` = строка подключения Neon
   - `JWT_SECRET` = случайная строка длиной >= 32 символа (в `render.yaml` настроено `generateValue: true`)
   - `APP_URL` = публичный URL вашего сервиса Render (например, `https://<service>.onrender.com`)
   - `SEED_ADMIN_PASSWORD` = желаемый временный пароль администратора (опционально; если не указывать, возьмите сгенерированный пароль из логов первого деплоя)
4. После завершения первого деплоя откройте вкладку **Logs** в Render:
   - Убедитесь, что есть строка `Connecting to external PostgreSQL database...` и `Inventory server running on port ...`.
   - Если `SEED_ADMIN_PASSWORD` не задавалась, скопируйте пароль из блока `[BOOTSTRAP CREDENTIALS]`.
5. Проверьте health-check: `GET https://<ваш-домен>/api/health` должен вернуть `{"ok":true,"database":"connected"}`.
6. Выполните первый вход под `admin`, сразу смените пароль через интерфейс и **удалите `SEED_ADMIN_PASSWORD`** из переменных окружения, если она больше не нужна (на уже созданного пользователя она больше не влияет).

## 5. Чек-лист при передаче проекта в эксплуатацию

- [ ] Задана внешняя PostgreSQL БД (`DATABASE_URL`), проверен ответ `/api/health` (`database: "connected"`).
- [ ] Сгенерирован уникальный `JWT_SECRET` (>= 32 символов).
- [ ] Настроен `APP_URL` и HTTPS-терминация с передачей `X-Forwarded-Proto` и `X-Forwarded-Host`.
- [ ] Выполнен первый вход под `admin` и **сменён начальный пароль**.
- [ ] Созданы реальные учётные записи сотрудников с минимально необходимыми ролями (`ADMIN`, `ENGINEER`, `USER`).
- [ ] Заполнены кабинеты и типы оборудования (вручную или через импорт Excel-реестра кафедры).
- [ ] Проверено скачивание печатных форм DOCX (QR-этикетки, акт списания, накладная) и работа сканера QR-кодов (требует HTTPS для доступа к камере браузера).
- [ ] Настроено регулярное резервное копирование базы данных PostgreSQL (`pg_dump` или snapshots в Neon).

## 6. Диагностика типовых проблем

| Симптом | Причина и решение |
| --- | --- |
| После перезапуска пропали данные / пользователи | Не задана `DATABASE_URL` (сервер работал на in-memory PGlite). Укажите строку подключения к внешнему PostgreSQL. |
| Ошибка `503` на `/api/health` | Недоступна БД или неверная строка `DATABASE_URL`. Проверьте сетевой доступ, SSL-параметры (`?sslmode=require`) и квоты Neon. |
| Сессии сбрасываются после редеплоя | Не задан постоянный `JWT_SECRET` в окружении — без него при каждом старте генерируется новый временный секрет. |
| Ошибка `403 Запрос отклонён политикой безопасности источника` | Заголовок `Origin` браузера не совпадает с `Host`/`X-Forwarded-Host` и `APP_URL`. Проверьте значение `APP_URL` и проброс `X-Forwarded-Host` на прокси. |
| Браузер не даёт доступ к камере в QR-сканере | WebRTC / `getUserMedia` работает только по **HTTPS** (или на `localhost`). Убедитесь, что сайт открыт по `https://` и разрешена политика `Permissions-Policy: camera=(self)`. |
| Блокировка входа на 15 минут (`429`) | Сработала защита от перебора паролей (5 неверных попыток подряд с одного IP для одного логина) или общий лимит `/api/auth` (40 запросов / 15 мин). Подождите истечения окна блокировки. |
