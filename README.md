# ИС «Учет материальных ценностей» (Кафедра ПиСП, ВГУ имени П.М. Машерова)

Информационная система учета материальных ценностей кафедры программного и системного программирования (ПиСП) ВГУ имени П.М. Машерова. Система предназначена для полного жизненного цикла учета оборудования: от постановки на баланс и импорта из Excel до QR-маркировки, инвентаризации, временной передачи, фиксации неисправностей, списания с формированием печатных форм DOCX и аудита действий пользователей.

## Основные возможности

- **Реестр оборудования**: отображение ID в базе данных, инвентарного номера, помещения, типа, балансовой и остаточной стоимости (BYN), срока эксплуатации, состояния и гарантии; поиск, фильтрация, массовое удаление.
- **Иерархия типов и настраиваемых полей**: дерево типов и подтипов оборудования с наследованием пользовательских дополнительных полей (`STRING`, `INTEGER`, `NUMBER`, `BOOLEAN`, `DATE`, `ENUM`, обязательность, множественные значения).
- **Импорт из Excel (`.xlsx`)**: готовый шаблон, автоматическое создание недостающих кабинетов и типов при импорте, экран подтверждения при обнаружении дубликатов (с выбором: пропустить дубликаты или обновить существующие позиции).
- **QR-маркировка и печать DOCX**:
  - Генерация индивидуальных и групповых QR-кодов.
  - Настраиваемый размер QR-кода (пресеты `1×1 см`, `2×2 см`, `3×3 см`, `5×5 см` и произвольный размер от `0.8` до `10 см`) с автоматическим пересчётом сетки на листе A4.
  - Встроенный сканер QR-кодов через камеру устройства и ручной поиск по коду/ID.
- **Инвентаризация**: проведение сессий инвентаризации с подтверждением наличия по QR-коду или из списка, контроль непроверенных позиций, сохранение истории проверок.
- **Учёт неисправностей и уведомления**: регистрация поломок (включая пакетную регистрацию по группе), уведомления ответственным ролям, закрытие ремонтом.
- **Временное пользование (передачи)**: фиксация выдачи оборудования сотрудникам с ожидаемым сроком возврата, отметка возврата и формирование накладной.
- **Списание и печатные формы DOCX**: статусы `PREPARING` → `DOCUMENTS_PREPARATION` → `WRITTEN_OFF`, формирование актов списания и накладных по 3 сценариям (дорогостоящее с драгметаллами, малоценное с ДМ, малоценное без ДМ).
- **Полноценное журналирование с разграничением прав**: 9 категорий событий, 3 уровня критичности (`INFO`, `WARNING`, `CRITICAL`), фильтрация видимости и возможностей по ролям, экспорт в `.xlsx` и ротация архива.
- **Безопасность**: обязательная авторизация, JWT (`HttpOnly` cookies + refresh-токены в БД), защита от перебора паролей и CSRF, политика сложности паролей.

## Технологический стек

| Слой | Технологии |
| --- | --- |
| **Frontend** | React `19`, TypeScript, Vite `8`, Tailwind CSS `4` (`@tailwindcss/vite`), `lucide-react`, `motion` |
| **Backend** | Node.js `>= 20`, Express `4`, TypeScript (`tsx` в dev, `esbuild` bundle в prod) |
| **База данных** | PostgreSQL (`pg`) + Drizzle ORM `0.45` (`drizzle-kit` `0.31`); для локального запуска без внешней БД — встроенный `@electric-sql/pglite` |
| **Аутентификация и защита** | `jsonwebtoken` (HS256), `bcryptjs` (cost 12), `cookie-parser`, встроенные rate-limiter, brute-force lock и Origin CSRF-проверка |
| **Документы и QR** | `docx` (генерация `.docx`), `xlsx` (импорт/экспорт Excel), `qrcode` (генерация QR), `jsqr` (распознавание QR с камеры) |

## Быстрый локальный запуск

### Требования
- **Node.js** версии `20.0.0` или выше
- **npm** (или `bun`)

### Шаги запуска
1. Установите зависимости:
   ```bash
   npm install
   ```
2. (Опционально) Создайте файл `.env` на основе `.env.example`.  
   Если переменная `DATABASE_URL` не задана, сервер автоматически поднимет встроенный **PGlite** (PostgreSQL 16 в памяти — удобно для тестирования, данные сбрасываются при перезапуске). Для сохранения данных между перезапусками укажите `DATABASE_URL` реального PostgreSQL.
3. Запустите приложение в режиме разработки:
   ```bash
   npm run dev
   ```
   Сервер и клиентская сборка Vite будут доступны по адресу: `http://localhost:3000`.

### Первый вход после старта на пустой БД
При первом запуске на пустой базе данных система создаёт **только одну учётную запись администратора** (без тестовых пользователей, без предустановленных типов оборудования, кабинетов и демо-техники):

- **Логин**: `admin`
- **Роль**: `ADMIN`
- **Пароль**:
  - если задана переменная окружения `SEED_ADMIN_PASSWORD` — используется её значение;
  - в режиме разработки (`NODE_ENV !== 'production'`), если `SEED_ADMIN_PASSWORD` не задана — используется пароль по умолчанию `PiSP_Adm1n!2026`;
  - в production (`NODE_ENV === 'production'`), если `SEED_ADMIN_PASSWORD` не задана — генерируется одноразовый криптостойкий пароль и **выводится один раз в консоль/логи сервера** при старте с префиксом `[BOOTSTRAP CREDENTIALS]`.

> После первого входа обязательно смените пароль администратора через меню профиля (**Сменить пароль**) и настройте справочники кабинетов, типов оборудования и учётные записи сотрудников (или выполните импорт из Excel).

## Доступные команды (`package.json`)

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск сервера разработки (`tsx server.ts` + Vite middleware на порту `3000`) |
| `npm run build` | Промышленная сборка фронтенда (`dist/`) и бандла сервера (`dist/server.js`) |
| `npm run start` | Запуск собранного production-приложения (`node dist/server.js`) |
| `npm run lint` | Проверка типов TypeScript без генерации файлов (`tsc --noEmit`) |
| `npm run db:push` | Применение схемы `src/db/schema.ts` к PostgreSQL через `drizzle-kit` |
| `npm run clean` | Удаление каталога сборки `dist/` |
